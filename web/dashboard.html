      Where the numbers come from

      provenance of this model

      Hardware descriptions are parsed from the Accel-Sim framework's tested GPU configs (GPGPU-Sim 4.x format). Occupancy uses the CUDA occupancy calculator rules; durations use a roofline model with latency floors from the simulator's L1, shared-memory and DRAM latencies. Stat names — gpu_tot_sim_cycle, gpu_ipc, gpu_occupancy, L2_BW — follow accel-sim's vocabulary, so a real simulation drops in seamlessly. Built with nvcc when CUDA 11–13 is present; analytical otherwise.

      Where cuvis goes next

      Every item stays GPU-free, deterministic and honest about what it models. The full list lives in docs/roadmap.md in the repository.

      1. Shipping now

        Device compare mode

        Pick two devices and see every chart side by side — the same kernel, two ceilings. Occupancy and roofline deltas are already per-device, so this is a UI story, not a model rewrite.

      2. Next

        Imported trace view

        Drop in a real accel-sim trace summary (a CSV of gpu_tot_sim_cycle-style stats) and replay it on the timeline, clearly labeled measured against the analytic model.

      3. Next

        Shareable dashboards

        Encode device and kernel selection in the URL hash so a dashboard view can be linked in a pull request or classroom note — no server, no storage.

      4. Next

        Kernel challenge cards

        Given a broken kernel (bad coalescing, bank conflicts), spot the bound on the roofline, then fix it in the playground and watch the chart move.

      5. Later

        WebGPU reference mode

        An optional real-GPU run through WebGPU compute, used only to sanity-check the teaching model — never as a timing source.

      6. Later

        Offline classroom pack

        A single self-contained export with the lesson packs inlined, so classes run with no network at all.
